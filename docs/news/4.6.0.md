# FactionsUUID 4.6.0

*Released June 28, 2026*


## The Upgrade Update

This update drastically improves upgrades. Manage them from in-game! Tons more added!

!!! warning "Notice Before Updating for Faction Vaults!"
    If you use the PlayerVaultsX integration for max vaults, your players will NOT have access to their vaults
    on first startup. This is *intentional*. Vaults are now an **upgrade**, which will start disabled so that you
    can configure it. Set up the upgrade to match how you want players getting vaults. Maybe that's a single upgrade
    that everyone gets, maybe that's multiple levels. Whichever it is, once you enable the upgrade with the values you want,
    **restart the server**. On restart, factions will be granted upgrade levels matching their previous vault limits (or
    smaller - if a faction had 3 vaults and there are two upgrades offering 2 and 4, they will be given the 2-vault upgrade).

### New Upgrades

A pile of new upgrades has been added. See the [Upgrades](../upgrades.md) page for the full list.

Some of my favorites include:

* Armor Durability Protection
* Beacon Effect Control
* Crop Yield Boost
* Mob Drop Boost
* Mob Experience Boost
* No Hunger Loss
* Territory Damage Boost / Resistance
* TNT bank is now an upgrade!

### In-Game Upgrade Management

* A new, Paper-only admin command, `/fa upgrades`, opens a management menu for configuring upgrades in-game.
* Changes are only applied once you review and confirm them.
* Requires the `factions.upgrades.manage` permission.

## Other Changes

### Translation

* Translation migration out of the legacy `lang.yml` has completed, with remaining messages now living in `translations.conf`.
* As always, back up your translations before upgrading.

### Invites

* Invites can now expire. Set invite expiry in `main.conf` to the number of minutes before an invite expires (or `0` to disable).

### Claim Limits

* New `main.conf` options let you cap the size of a single contiguous claim for normal factions:
    * `contiguousTotalChunks` — maximum number of chunks in one contiguous claim (`0` disables the check).
    * `contiguousDistance` — maximum width, in chunks, across one contiguous claim (`0` disables the check).

### Remaining Changes

* The "damage attempted" warning normally sent to a defender is now suppressed when the attacker is vanished.
    * Controlled by `disableNotificationWhenAttackerVanished` in `main.conf` (default `true`).
* The `/f map` command output has been modernized.
* Announcements (`/f announce`) now support MiniMessage formatting.
* Faction shields are now scheduled more reliably.


### Developer API

Some highlights:

* Added `Participator#describeTo(Participator)`.
    * Provides relation-colored faction tag or player name with title for same-faction or faction tag for non-same faction.
    * Same output you get from the `<faction>` and `<player>` tag defaults.
* Added component method for adding faction announcements. Deprecated the legacy one, finally.
* Added `Faction#clearInvites()` and made `invites()` return a copy.
* Added `Faction#inviteExpiry(FPlayer)`.
* Deprecated Relation and Role public fields. You should immediately move to using the methods `translation()` and `value()`.
    * The `nicename` field is now always equal to `name()` until removal.
* Deprecated the entirety of `RelationUtil`.
* Deprecated `Faction#maxVaults(int)` which now does nothing. 

### 4.6.1 Changes

* Fixed up flight particles!
    * The ability to specify particle was accidentally missing from the command and now it's back!
    * Added new config entries to specify the flight color or, by default, use relation colors!
* Added new permission context `factionsuuid:banned-by`, based on user request. 
* Added new command `/fa get <faction> <key>`
    * Currently only supports `id` key and outputs the faction's internal ID.
    * Useful for the [permission contexts](../contexts.md) that use the ID.
* Fixes:
    * Fixed wrong translation usage on DTR regen and loss reduction - they were using the power translations. 
    * Added missing check for relation perms on the relation command.
    * Removed unused permissions from registration, to minimize confusion in perms plugin autocompletes.
    * Cleans up zone claims for zones that no longer exist.
        * You may see a message about this on first startup as it also cleans at startup to catch ones missed before this fix. 
    * A dozen other goofy lil bugs.
* Developer changes:
    * Deprecated a bunch of public fields that should not have been used over their toStrings or other methods.
    * Added a bunch of AvailableSince and Deprecated annotations, and also more clearly labeled all deprecations as for removal in 5.0.0.
    * Flagged a bunch of clearly internal stuff properly as Internal.
